## 二、Blocker 与 Major 问题详述（按维度归并，Minor 见附录清单）

### Blocker

**B1. 非 ASCII API Key 触发 UTF-8 边界 panic，release 下 panic=abort 直接闪退**
📍 `src-tauri/src/storage.rs:185`、`src-tauri/src/commands.rs:620-621`、`commands.rs:669-670`；放大器 `src-tauri/Cargo.toml:43`（`panic = "abort"`）

❌ 现状（三处同款）：

```rust
// storage.rs:185
format!("{}...{}", &key[..4], &key[key.len() - 4..])
```

`&key[..4]` 按**字节**切片。Key 由用户自由输入，国产 API 常见含多字节字符的 token，切片点落在字符中间即 panic；`list_providers`（启动即调用，对每行经 `row_to_provider` 调 `mask_key`）触发后，abort 模式下无 unwind 机会——**应用启动即闪退**。

✅ 修改后（三处统一，抽为共用函数）：

```rust
// storage.rs
pub fn mask_key(key: &str) -> String {
    if key.chars().count() <= 8 { return "****".to_string(); }
    let head: String = key.chars().take(4).collect();
    let tail: String = key.chars().rev().take(4).collect::<String>().chars().rev().collect();
    format!("{}...{}", head, tail)
}
```

`commands.rs` 两处内联脱敏（`:615-623`、`:662-673`）删除，改调 `storage::mask_key()`（顺带解决现有三份脱敏逻辑短 key 行为不一致的问题）。

📝 理由：确定性可触发的崩溃路径 + 进程级闪退，修复成本极低，收益极高。

### Major · 维度3 健壮性与安全

**R1. 主密钥静默轮换：keyring 读取失败会生成并覆盖新主密钥，所有已存 API Key 永久不可解**
📍 `src-tauri/src/storage.rs:130-145`

❌ `get_password()` 因凭据管理器暂时不可用（企业策略、DPAPI 异常、锁屏初期）返回 Err 时，代码不报错，而是**生成新随机主密钥并覆盖写入**。下次启动恢复后旧密文全部解密失败，用户全部服务商 Key 失效且无提示。

✅ `get_password` 失败时返回错误 `"无法读取系统凭据管理器，拒绝轮换主密钥以避免数据丢失: {e}"`；仅首次（entry 明确不存在）才生成。进程内用 `static MASTER_KEY: OnceLock<[u8;32]>` 缓存（顺带修复 R6：当前每行解密都走一次 DPAPI 系统调用）。

📝 理由：密钥轮换必须是有意识的、可通知的操作；当前实现在故障场景下制造静默数据损坏。

**R2. 解密失败被 `unwrap_or_default()` 静默吞掉**
📍 `src-tauri/src/storage.rs:190`、`commands.rs:26、:614、:663、:688`

❌ `decrypt_secret(&enc).unwrap_or_default()` 散布 5 处。主密钥丢失/密文损坏时表现为 `has_key=false`、"API Key 无效"（401），用户永远查不到真正原因——与 R1 互为因果。

✅ 区分"未设置 Key"（密文为空 → 空串，正常）与"解密失败"（非空但报错 → `row_to_provider` 中置 `key_error: bool` 透出前端，前端显示"密钥损坏，请重新填写"；`ProviderConfig::from` 处解密失败应返回 `Err` 而非空 key 上送）。

**F1. `chatStore.send()` 主流程三处 invoke 无 try/catch，失败时 unhandled rejection 且停止按钮永久卡死**
📍 `src/stores/chatStore.ts:163、:180、:319`

❌ `:163` `createConversation` 失败 → 用户消息直接丢失且无提示；`:180` `addMessage` 失败时 `sending` 已被置 true（`:225`）→ **停止按钮永久卡住、会话状态损坏**。对比 `:245`、`:276` 均有 try/catch，属遗漏而非风格。

✅ `send()` 外层统一 try/catch，失败时 `updateAssistant({status:"error", error:...})` 并确保 `sending:false`；`loadConversations`（`:109`）、`selectConversation`（`:123`）等同加 `.catch` 兜底。

**F2. 画廊删除/收藏失败无提示、UI 与数据不一致** 📍 `src/components/GalleryView.tsx:120-135` — 两处 await 无 try/catch，失败时 unhandled rejection，按钮看似无响应。加 catch + 轻提示。

### 5.2 工程化手段建议（按引入顺序）

1. **第 1 周**：git 初始化 + ESLint 9 flat config + Prettier + `.editorconfig` + `lint-staged`（simple-git-hooks）；Rust `cargo fmt --check` + `clippy -- -D warnings` 写入 `package.json` scripts 与 CI。
2. **第 2 周**：前端测试设施（Vitest + React Testing Library），优先覆盖 `chatStore.send`（拆分为可测函数后）与 `lib/api.ts` 序列化；后端补 `commands.rs` 拆分后的集成测试。
3. **第 3 周**：CI 流水线（GitHub Actions / 自建）：`pnpm lint && pnpm build && cargo clippy && cargo test && cargo fmt --check`，产物构建 + Tauri 打包。
4. **持续**：代码审查 Checklist（见 5.3）嵌入 PR 模板；`CHANGELOG.md` 已有，配 Conventional Commits + `changesets` 或手工维护。

### 5.3 《团队开发规范 Checklist》模板（可复用）

> 用法：每次提交/PR 自查；评审时逐条勾选。标 ★ 为合并阻断项。

**A. 合规性**

- [ ] ★ 变量/函数/类/文件命名见名知义，无 `chrono_now()` 式误导命名
- [ ] ★ 无魔法数字；常量具名且集中存放
- [ ] 缩进/引号/分号经 Prettier/EditorConfig 统一，CI 有 format 检查
- [ ] 无 `// eslint-disable` 死注释；如需压制必须附原因与 issue 链接
- [ ] 提交信息符合 Conventional Commits（`feat:/fix:/refactor:` + 中文/英文描述）

**B. 架构与可维护性**

- [ ] ★ 单文件 < 400 行；超过必须说明理由或拆分
- [ ] ★ 无复制粘贴超过 10 行的重复代码（DRY）
- [ ] ★ 无硬编码密钥/IP/绝对路径；配置全部外置
- [ ] 模块依赖单向，生产代码不依赖 mock/test 工具
- [ ] 同一概念单一事实源（结构体/类型不镜像多份）

**C. 健壮性与安全**

- [ ] ★ 所有 `await`/`invoke` 调用有 try/catch 或 `.catch` 兜底，失败有用户可感知反馈
- [ ] ★ 字符串切片/索引考虑 UTF-8 边界（按 `chars()` 不按字节）
- [ ] ★ 密钥/凭据操作 fail-loud：解密失败、凭据读取失败必须报错或显式标记，禁止 `unwrap_or_default()` 吞错
- [ ] SQL 全部参数化；无字符串拼接
- [ ] 用户输入（长度/类型/范围）在进入核心逻辑前校验
- [ ] 日志无敏感信息（key/token/密文），关键节点（导入/导出/密钥操作/重试）留痕
- [ ] 应用设置 CSP 等纵深防御头

**D. 性能与可扩展性**

- [ ] zustand/redux 订阅使用 selector，禁止整店订阅渲染热区组件
- [ ] 长列表（>50 项或含大对象）虚拟化
- [ ] HTTP client / runtime / 重量级资源全局复用，禁止每请求新建
- [ ] useEffect 清理定时器/监听/abort 控制器
- [ ] 读路径无副作用；写路径有事务
- [ ] 新增 provider/adapter 只需实现 trait + 注册一处

**E. 测试与文档**

- [ ] 核心业务流（发送/生成/导入导出）有测试
- [ ] 公共函数有 doc comment 或类型签名自解释
- [ ] 行为变更同步更新 CHANGELOG 与产品文档
